# Каталог уязвимостей

Консольная утилита на Python загружает два JSON-фида из тестового задания в SQLite. По названию продукта она подбирает новейшую версию из каталога без известных по фиду уязвимостей. По названию и версии она показывает записи об уязвимостях, которые затрагивают эту версию.

## Запуск

Нужен Python 3.10 или новее со стандартным модулем `sqlite3`. Команды выполняются из корня проекта. Исходные JSON-файлы находятся в `data/`. Если команда `python` не запускает установленный интерпретатор, подставьте полный путь к `python.exe`.

```text
python -m vuln_catalog import
python -m vuln_catalog recommend "7-Zip"
python -m vuln_catalog check "7-Zip" 24.06
python -m vuln_catalog check "7-Zip" 24.07
```

Импорт создаёт `catalog.sqlite3` и загружает 24 продукта, 834 версии и 135 записей об уязвимостях. В архиве для сдачи эта база уже собрана. Команда импорта позволяет пересобрать её из исходных данных. Подбор для 7-Zip возвращает `24.09`. Проверка `24.06` показывает статью `KLA77436`. Для `24.07` уязвимости по фиду не найдены.

При необходимости можно указать свой путь к базе и исходным файлам.

```text
python -m vuln_catalog --db review.sqlite3 import --versions data/versions.json --vulnerabilities data/vulnerabilities.json
python -m vuln_catalog --db review.sqlite3 check "Git for Windows" 2.43.4
python -m vuln_catalog --help
python -m unittest discover -s tests -v
```

Поиск использует полное название продукта, игнорируя регистр латинских букв. Если в базе есть продукты с одинаковым названием от разных производителей, добавьте `--vendor` после названия команды. Для версии вне каталога `check` сообщает об этом и проверяет её по имеющимся диапазонам. Команды возвращают код 0 после успешного запроса, в том числе если уязвимости или подходящие версии отсутствуют. Код 1 означает ошибку данных или запроса, код 2 — ошибку синтаксиса команды.

## Схема и модули

- `products` хранит уникальные пары «производитель и название».
- `versions` хранит версии с внешним ключом на продукт. Пара «продукт и версия» уникальна.
- `vulnerabilities` хранит исходные границы, описание и дату. Ключ включает продукт, идентификатор статьи и обе границы. У одной статьи может быть несколько диапазонов, а границы диапазона могут отсутствовать в каталоге версий.

`feeds.py` отвечает за разбор и проверку входных файлов. `database.py` хранит схему и выполняет SQL-запросы. `domain.py` сравнивает версии и применяет общие правила для обеих команд. `cli.py` принимает аргументы и выводит результат.

SQLite выбран для запуска на одном компьютере и воспроизводимой проверки без отдельного сервера. Повторный импорт заменяет предыдущий снимок в одной транзакции. Если импорт прервётся или обнаружит конфликт ключей, ранее загруженный снимок сохранится. Запросы открывают базу в режиме чтения.

## Правила проверки версий

Компоненты версии сравниваются как целые числа. Например, `15.10` больше `15.9`, а `24.07` эквивалентна `24.7.0`. Исходное написание версии сохраняется для вывода. Допустимы цифровые компоненты, разделённые точками.

По умолчанию запись затрагивает версии от первой уязвимой включительно до первой исправленной исключительно. Подбор проверяет версии из каталога от самой новой к самой старой. Результат отражает только сведения в загруженном снимке.

В нескольких статьях одна уязвимость имеет отдельные исправления для разных веток, а в фиде нижняя граница для нескольких записей указана как `0`. Чтобы исправление для одной ветки не влияло на соседнюю, для этих статей применяются ограничения из описаний Kaspersky. Версии исправлений и состав записей берутся из исходных JSON. Программа работает офлайн.

| Статья | Правило |
| --- | --- |
| [KLA67449](https://threats.kaspersky.com/en/vulnerability/KLA67449/) | Для Git for Windows сравниваются версии в пределах ветки `major.minor` |
| [KLA79193](https://threats.kaspersky.com/en/vulnerability/KLA79193/) | Для VirtualBox сравниваются версии в пределах ветки `major.minor` |
| [KLA67224](https://threats.kaspersky.com/en/vulnerability/KLA67224/), [KLA71453](https://threats.kaspersky.com/en/vulnerability/KLA71453/), [KLA77143](https://threats.kaspersky.com/en/vulnerability/KLA77143/) | Для PostgreSQL сравниваются версии с одинаковым первым компонентом |
| [KLA65144](https://threats.kaspersky.com/en/vulnerability/KLA65144/) | Для Tomcat запись с исправлением `8.5.99` действует в ветке `8.5.x`, а запись с `9.0.86` — в ветке `9.x` |
| [KLA67582](https://threats.kaspersky.com/en/vulnerability/KLA67582/), [KLA73989](https://threats.kaspersky.com/en/vulnerability/KLA73989/) | Для LibreOffice `24.x` и Thunderbird `128.x` исправления ограничены соответствующей веткой. Записи с более ранними исправлениями сохраняют исходный диапазон |

У [KLA70478](https://threats.kaspersky.com/en/vulnerability/KLA70478/) границы `128` и `128.0` совпадают при числовом сравнении. Исходные значения сохраняются в базе. При проверке нижняя граница считается неопределённой согласно статье, которая указывает все версии Thunderbird до `128.0`.

У нового фида с другими статьями для нескольких веток может понадобиться уточнить ограничения. Утилита применяет к таким записям исходные интервалы, пока для статьи не задано отдельное правило.
